## API keys

`POST /api/v1/api-keys/` (`APIKeyCreate`): `name*`, and booleans `can_queue` (default true), `can_control_printer` (false), `can_read_status` (true), `can_manage_library` (true), `can_manage_inventory`, `can_manage_maintenance`, `can_manage_archives`, `can_manage_projects` (all true by default: **turn these off**), `can_access_cloud` (false), `can_update_energy_cost` (false), `printer_ids` (optional allow-list), `expires_at`.

os2slice needs: `can_read_status`, `can_manage_library` (upload + slice; `/slicer/presets` is gated on `LIBRARY_UPLOAD`), `can_queue`. Everything else off.

### `SliceRequest`

- Presets, source-aware: `printer_preset`, `process_preset`, `filament_preset` (or `filament_presets[]` per plate slot), each a `PresetRef {source*: "orca_cloud"|"cloud"|"local"|"standard", id*: str}`. For `standard`, `id` is the preset name. The integer `*_preset_id` fields are deprecated.
- `process_overrides`: **a sparse `{option_key: value}` object**, "the user's own process-setting edits from the slice modal's settings panel". This is where walls, infill and supports go (D-14). The Bambu Studio keys still need confirming in the spike: probably `wall_loops`, `sparse_infill_density` (`"25%"`), `enable_support`, `support_type` (`normal(auto)` / `tree(auto)`), `support_on_build_plate_only`.
- `auto_orient` (default false: "it rotates geometry"), `auto_arrange` (default false). Good for D-14: we orient the mesh ourselves and leave these off unless the user asks for auto-orient.
- `bed_type` (e.g. "Cool Plate", "Engineering Plate", …), `plate`, `export_3mf`, `filament_colours[]`, `use_embedded_settings` / `design_overrides` (3MF only).

- **2026-10-01, virtual printers (read-only; BamBuddy wiki `docs/features/virtual-printer.md`):**
  - `GET /virtual-printers` → `{"printers": [{id, name, enabled, mode, model, serial, target_printer_id, auto_dispatch, queue_force_color_match, save_ams_mapping, bind_ip, status: {running}}]}`; `GET /virtual-printers/{id}/diagnostic` → `{overall, checks: [{id, status}]}` (bind interface, ports 990/8883/3000/3002, certificate…); `GET /settings/virtual-printer/models` maps model codes (`O1D` = H2D, `BL-P001` = X1C, `N1` = A1 Mini).
  - `GET /virtual-printers/ca-certificate` → `{"pem", "fingerprint_sha256", "not_valid_after"}`: one CA for every VP, which a slicer must have appended to its `resources/cert/printer.cer`. The web Bambu Studio add-on does this at every start.
  - Each enabled VP needs **its own IP** on the BamBuddy host (BamBuddy runs with host networking on HAOS): all services (bind 3000/3002, MQTT 8883, FTPS 990, passive FTP 50000+, RTSP 322) listen on that IP. SSDP discovery can't reach the web session's container, so VPs are added there by IP.
  - With a **target printer**, a server-mode VP mirrors the real printer's live state (AMS, nozzles, camera) to the slicer and auto-takes the printer's access code; files sent with **Send** (not Print) land in BamBuddy. Print Queue mode's `auto_dispatch` starts the job when the printer is free; off = waits for Start.
